pmap 为现有系统 OpenSSH 环境提供图形控制面板：选择主机，输入 `8000` 或 `8000:80`，开启或停止本地到远程回环地址的端口转发。支持 macOS 14+，构建为 Intel 与 Apple Silicon 通用二进制。

当前改造分支为下一版 0.2.0（4）候选版本；`v0.1.5` 标签保留改造前基线。尚未完成正式 App Store 签名、上传或审核。

## 构建与启动

```bash
cd /Users/jiyeqian/Workspace/pmap
./test.sh
./build.sh
./scripts/verify-bundle.sh pmap.app
open /Users/jiyeqian/Workspace/pmap/pmap.app
```

需要完整 Xcode 工具链。启动新构建前先正常退出旧实例；构建脚本会拒绝替换检测到的运行中输出。图标或签名失败会阻断构建。普通本地包使用临时签名，没有 Apple 公证；这不等同于正式商店分发。

沙盒候选构建：

```bash
cd /Users/jiyeqian/Workspace/pmap
PMAP_SANDBOX=1 ./build.sh
PMAP_REQUIRE_SANDBOX=1 ./scripts/verify-bundle.sh pmap-sandbox.app
open /Users/jiyeqian/Workspace/pmap/pmap-sandbox.app
```

完整 Xcode 工程、真实 SSH 集成测试和人工验收方法见 [商店准备与验收](./docs/APP_STORE.md)。

## 首次使用

1. 普通版默认读取 `~/.ssh/config`；沙盒版点击“选择配置…”授权配置文件。文件名和位置不限。
2. 主机读取后即可浏览。首次选择主机时确认配置可信；首次主机指纹验证和密钥解锁仍在终端完成。
3. 若提示“需要授权”，点击同一行的“授权…”选择所需文件或符号链接的实际目标。
4. 从旧版迁移至沙盒版：在 `…` → “导入旧版配置…”中选择旧 `config.json`，确认替换当前端口、语言及上次连接记录。原文件不变，当前 SSH 文件授权保留，不导入源文件中的信任或授权。
5. 旧数据需要重新授权或确认信任时，原来的开启端口会保留。选择原主机或点击“恢复上次连接…”后，确认信任即可恢复；选择其他主机不会沿用原主机的开启状态。
6. 添加端口，用浏览器或客户端验证实际服务响应。

配置变化会在重新打开主面板时自动读取。底部依次是版本号、选项、语言图标和退出图标，不再有独立设置窗口。

pmap 运行非交互式系统 SSH，强制严格主机校验，不自动信任新主机或接受变更的主机密钥。SSH Agent、系统钥匙串和外部命令在沙盒内可能受限，不能保证与终端完全一致。

## 操作与状态

| 操作 | 行为 |
| --- | --- |
| 输入 `8000` | 本地 `127.0.0.1:8000` → 远程 `127.0.0.1:8000` |
| 输入 `8000:80` | 本地 `127.0.0.1:8000` → 远程 `127.0.0.1:80` |
| 输入 `5432:5432#数据库` | 添加转发并显示备注 |
| 点击端口按钮 | 开启，或停止转发/重试 |
| 点击删除按钮 | 清理转发后删除规则；清理失败时保留规则与错误 |
| 主机菜单“断开” | 断开当前主机及端口，取消待恢复状态 |
| 地球图标 | 切换并保存界面语言 |
| 省略号菜单 | 选择配置、导入旧配置、启动恢复、自动重连、通知、重置授权；出错时可复制诊断 |
| 电源图标 | 保存期望状态，异步释放受管 SSH 会话与监听 |

端口绿灯表示转发请求已建立，**不表示远端服务健康**；红灯表示失败；主机未连接时端口为灰。菜单栏圆点按端口顺序轮播，不能代替主机错误详情。端口按钮提供辅助功能名称和状态，长列表支持滚动。

端口范围为 **1–65535**。本地端口不能重复，远程端口可以重复。非法格式及重复本地端口回车后显示红色提示，继续输入即清除提示。`#备注` 在创建时填写，之后以次级灰字显示；悬停端口按钮可查看完整备注。

自动保存端口、备注、选中主机、期望开启状态和语言。正常退出会关闭受管转发；再次启动时，若“启动时恢复”已开启且配置可用、可信，自动连接上次主机并恢复端口。

自动重试仅用于可恢复故障；初次连接失败按 3、6、12、24、30 秒退避，端口转发失败按 5、10、20、30 秒退避。认证、主机密钥及明确禁止转发等错误需要用户处理，再从主机菜单重新选择该主机；失败端口可先点停，再点开启。端口被占用时尽可能显示占用进程，沙盒不允许查询时仍显示端口占用错误。

通知默认关闭，在 `…` → “连接状态通知”中开启时申请系统权限。开启且系统允许后，连接断开、重连成功和失败端口恢复会通知；重连成功仅表示主连接恢复，通知中的端口数为待恢复数。系统拒绝权限后需在系统设置中允许。

| 状态 | 含义 |
| --- | --- |
| 主机绿 / 红 / 灰 | 已连接 / 连接失败 / 断开或连接中 |
| 端口绿 / 红 / 灰 | 转发已建立 / 转发失败 / 停止或主机未连接 |
| 菜单栏圆点 | 按端口顺序每 1.5 秒轮播其颜色；主机未连接或无端口时为灰 |

主机失败先检查主机错误；端口失败查看该行悬停提示。菜单栏圆点表示端口状态，不单独表示主机健康。

## 配置与兼容性

普通构建配置：`~/Library/Application Support/Pmap/config.json`。沙盒构建保存在对应应用容器内，应用支持目录由系统 API 确定；两种构建不自动互相迁移配置，可用“导入旧版配置…”由用户选择导入。旧版文件位于 `~/Library/Application Support/Pmap/config.json`。

旧版核心配置仍可读取：

```json
{
  "host": "myserver",
  "adhoc": [{ "local": 3080, "remote": 3080, "note": "deepseek" }],
  "active": [3080],
  "lang": "zh"
}
```

`host` 是上次主机，`adhoc` 是端口与备注，`active` 是期望恢复的本地端口，`lang` 是界面语言。新授权及连接偏好由程序管理，无需手动填写。

配置原子保存并校验端口。损坏或不支持的配置版本会提示错误并保留原文件，不会静默覆盖。`active` 字段保存用户期望恢复的端口，而不是声称这些端口在任何时刻都实际连通。

pmap 只读系统 SSH 配置和密钥。主机列表沿用 0.1.5 规则：排除含点、通配及否定模式，排除明确指向 `localhost`、`127.0.0.1`、`::1` 的别名；一行多个别名也会过滤。支持有界递归 Include。本机过滤只静态检查 Host/HostName，不执行 Match exec 或 DNS 查询；条件配置需由用户自行确认。含点主机需要使用无点别名。User、HostName、Port、IdentityFile 和 ProxyJump 交给系统 OpenSSH 解析。配置里的 LocalCommand、Agent/X11 转发和额外端口映射被禁用，仅管理面板声明的本地转发。

ProxyCommand 和 Match exec 可能执行程序，因此仅在用户确认信任配置后运行，并仍受沙盒权限约束。完整边界见 [SSH 兼容契约](./docs/APP_STORE.md)。

与 0.1.5 的逐项恢复及保留差异见 [版本差异](./docs/VERSION_COMPARISON.md)。

## 故障诊断

出错时使用 `…` → “复制脱敏诊断”。报告包含构建号、主机状态、固定错误类别、端口错误分类计数、配置读取与信任状态，以及当前语言的恢复步骤和验证方法。主机故障会明确标记，不会因 Storage/Access 为 false 而被隐藏。

报告不含主机名、地址、端口号、路径、进程名、备注或 SSH 原始输出；只提供建议，不自动修改配置、授权或信任记录。`Access error: false` 不保证 SSH 能读取全部引用文件；主机密钥错误需按报告先在终端核对指纹、必要时授权实际 known_hosts。转发绿灯仍需用实际客户端验证服务。未知错误需在本机查看原文，分享前自行脱敏。

## 隐私与发布

pmap 连接你指定的服务器，不向开发者发送遥测，不含广告或统计 SDK。密钥不复制到应用配置；诊断复制不含主机名、地址、路径和备注。完整说明见 [隐私政策](./docs/PRIVACY.md)，点击版本号的“隐私政策”也可阅读。

商店所需公开隐私政策 URL、发布主体、审核测试服务和加密出口申报仍需在正式提交前确认。现有文案为 [商店材料草案](./docs/STORE_METADATA.md)，不表示已上线。
