## 已执行的验证

- 57 项 Swift Testing 测试、9 个套件全部通过。包含主机切换、删除途中转发、停止失败端口、取消失败、退出竞态、关闭退避重连、损坏配置保护、进程超时/取消和 stdout/stderr 排空。
- 普通版 `build.sh` 双架构优化构建通过；沙盒版 Xcode Debug 双架构构建通过；两种最终包的 plist、临时签名、架构、图标与隐私资源检查通过。
- 从零启动临时 sshd 与 HTTP 服务的集成脚本通过：沙盒内系统 SSH 连接、真实 HTTP 数据穿透、取消转发释放端口、会话关闭释放端口、拒绝未知主机。包含超长容器目录场景。
- 实际系统文件选择器验证：取消不授权；授权无密钥测试目录后可读取配置；正常退出重启后仍有效；撤销后恢复未授权提示。未授权真实 `.ssh` 或读取真实私钥。
- 真实窗口验证设置入口、隐私说明、辅助功能名称/状态和正常退出快捷键。开发用虚构数据截图见 [设置](./screenshots/settings-en.png) 与 [隐私](./screenshots/privacy-en.png)，不是商店成品截图。
- `git diff --check` 和 shell 语法检查通过。

执行环境对编译缓存、嵌套构建沙盒、图标工具和回环监听有限制；已通过临时缓存、SwiftPM 的 `--disable-sandbox` 与受控的正常 macOS 执行完成验证。关闭的是 SwiftPM 构建沙盒，应用的 App Sandbox 保持启用。无证书 Xcode 构建提示 Hardened Runtime 随临时签名关闭，因此没有声称通过正式 Hardened Runtime 分发验证。

## 启动与验收

先正常退出旧 pmap，分别测试两种候选包，不要同时启动：

```bash
open /Users/jiyeqian/Workspace/pmap/pmap.app
```

```bash
open /Users/jiyeqian/Workspace/pmap/pmap-sandbox.app
```

两包均为 0.2.0（1），分别使用 `dev.local.pmap` 和 `dev.local.pmap.sandbox`，配置位置彼此独立。沙盒版首次需要从设置选择 SSH 文件夹，再确认配置信任。测试授权已撤销，正式验收应由使用者选择真实配置。

最小验收流程：打开设置 → 确认配置信任与文件授权 → 选择测试主机 → 添加端口 → 用浏览器验证远端响应 → 停止/删除 → 退出 → 确认端口释放。详细故障、恢复和兼容性步骤见 [商店准备与验收](./APP_STORE.md)。

## 正式发布与实机验收剩余项

- 开发者会员、发布主体、正式 Bundle ID、团队、证书、描述文件与正式签名/归档/上传验证。
- 已部署且可访问的 HTTPS 隐私政策 URL（归档脚本要求 `PMAP_PRIVACY_POLICY_URL`）、支持联系方式、商店截图与问卷。
- 审核专用 SSH 服务、凭据和可信指纹；商店隐私与加密出口申报应根据最终实现确认，不自动声明豁免。
- 真实环境的 SSH Agent、钥匙串、加密/硬件密钥、ProxyJump/ProxyCommand 与外部 Include；任意系统 SSH 配置完全兼容不在承诺范围内。
- macOS 14、Intel 实机、网络中断/睡眠唤醒、VoiceOver、多显示器和浅色外观的完整人工验收。双架构编译不能替代实机验证。
- 强制终止、系统崩溃与关机的进程清理仍需专门实机测试；正常退出通过不代表这些场景通过。

这些剩余项是明确的发布门槛，不属于已通过项目。商店元数据与审核说明草案在 [STORE_METADATA.md](./STORE_METADATA.md)，隐私政策在 [PRIVACY.md](./PRIVACY.md)。
